🔹MODULES :- A function use for multiple usrs to use code & configs via simple call

Advantage: 
1.-Modularity: Break configs into focused, self-contained components for easier management.

2.Reusability: Reuse modules across projects to avoid duplication and ensure consistency.

Collaboration: Teams can work on separate modules independently, reducing conflicts.

Versioning: Modules can be versioned so updates are adopted intentionally.

Abstraction: Hide resource complexity behind simple input/output interfaces.

Testability: Test modules individually to catch errors before reuse.


Documentation & clarity: Well-defined variables/outputs make usage self-documenting.

Security & compliance: Encapsulate best practices (security groups, IAM, etc.) for consistent enforcement.

🔹 2. Structure kaise hota hai

Example folder:

terraform-project/
│
├── main.tf            <-- root file (module call yahan hota hai)
├── outputs.tf         <-- root outputs
├── variables.tf       <-- root variables (input for module)
│
└── modules/
     └── ec2/
          ├── main.tf          <-- EC2 create hone wala actual code
          ├── variables.tf     <-- module inputs (name, ami, etc)
          ├── outputs.tf       <-- module outputs (public_ip, id, etc)

🔹 3. Kaam ka flow (simple version)

1️⃣ Module ke andar:
Tu define karta hai kaise EC2 banega.

Example:

# modules/ec2/main.tf
resource "aws_instance" "this" {
  ami           = var.ami
  instance_type = var.instance_type
  tags = {
    Name = var.instance_name
  }
}


Yahan module ke andar tu sirf logic likhta hai — par ye run tabhi hoga jab koi is module ko call karega.

2️⃣ Root/main.tf me:
Tu is module ko “call” karta hai — aur variables deta hai:

module "my_ec2" {
  source         = "./modules/ec2"
  ami            = "ami-0abcd1234"
  instance_type  = "t2.micro"
  instance_name  = "MyInstance"
}


Soch le — ye “module call” karta hai aur bolta hai “jao EC2 bana ke aa jao”.

3️⃣ Output kyu root me aur module me dono jagah bante hain?

👉 Module ke outputs.tf:
Yahan tu likhta hai ki module se kya cheez bahar bhejni hai (e.g., public IP, instance ID).

# modules/ec2/outputs.tf
output "public_ip" {
  value = aws_instance.this.public_ip
}


👉 Root outputs.tf:
Yahan tu likhta hai ki jab user terraform apply kare to usse screen pe kya dikhana hai.

# root/outputs.tf
output "ec2_public_ip" {
  value = module.my_ec2.public_ip
}


Yani:

Module output → internal result nikalta hai.

Root output → woh result console pe dikhata hai.
